# 작업 기록

## 2026-08-07 — 몬스터 모션 GIF 일괄 생성

### 작업 목표

`Assets/ThirdParty/01_비인간캐릭터` 내부 몬스터의 모션을 SFX 선택용 움짤로 확인할 수 있도록 GIF로 변환했다.

### 승인된 작업 범위

- 대상: `Assets/ThirdParty/01_비인간캐릭터` 내부의 몬스터 프리팹과 Animator 모션
- 출력 폴더: `Assets/ThirdParty/01_비인간캐릭터/몬스터모션`
- 출력 형식: `몬스터이름_모션이름.gif`
- 원본 FBX, 프리팹, 씬, 머티리얼은 수정하지 않음

### 처리 결과

- 수집한 고유 모션: 6,316개
- 생성한 GIF: 6,316개
- 렌더 프레임: 45,770개
- 검증 실패 GIF: 0개
- 남은 임시 프레임 폴더: 0개
- GIF 총 용량: 약 56.27MB

GIF는 160×160 해상도, 8fps, 최대 2초 길이로 생성했다. 모션 이름이 중복될 때는 기존 파일을 덮어쓰지 않도록 `_02`, `_03`과 같은 충돌 번호를 붙였다.

### 구현 구조

작업을 다음 단계로 분리했다.

1. Unity Editor Utility가 프리팹의 `Animator`에서 모션을 수집한다.
2. Unity의 `PreviewRenderUtility`로 각 모션을 프레임 이미지로 렌더링한다.
3. 외부 Pillow 인코더가 PNG 프레임을 GIF로 묶는다.
4. Pillow로 모든 GIF를 다시 열어 파일 손상 여부를 검증한다.

주요 도구는 [MonsterMotionGifExporter.cs](../Assets/Editor/Tools/MonsterMotionGifExporter.cs)와 [encode_monster_motion_gifs.py](../tools/encode_monster_motion_gifs.py)다.

### 설계와 책임 분리

- `MonsterMotionGifExporter`: Unity 자산 탐색, 모션 수집, 렌더링, 출력 이름 결정 담당
- `encode_monster_motion_gifs.py`: PNG 프레임의 GIF 인코딩만 담당
- 원본 머티리얼은 보존하고, 렌더링 인스턴스에만 기본 셰이더를 적용해 누락 셰이더로 인한 마젠타 표시를 방지했다.
- 출력 파일명 충돌은 별도 이름 결정 로직에서 처리해 렌더링 로직과 분리했다.
- 임시 Unity 프로젝트와 프레임은 작업 종료 후 제거했다.

### 학습 포인트

- Unity의 `AnimationClip`은 프리팹의 `AnimatorController`에서 수집할 수 있다.
- `AnimationMode.SampleAnimationClip`으로 특정 시간의 모션을 샘플링할 수 있다.
- `PreviewRenderUtility`는 실제 씬을 변경하지 않고 에디터용 렌더 이미지를 만들 때 사용할 수 있다.
- 렌더링과 GIF 인코딩을 분리하면 Unity는 3D 모션 처리에 집중하고, 이미지 포맷 변환은 별도 도구가 담당하게 되어 의존성이 낮아진다.
- 대량 작업은 `수집 → 렌더링 → 인코딩 → 검증`으로 나누면 중간 결과와 실패 지점을 확인하기 쉽다.

### 검증 방법

- 출력 폴더의 GIF 개수를 렌더링 대상 수와 비교했다.
- Pillow의 `verify()`로 모든 GIF를 열어 확인했다.
- 모든 GIF에서 오류가 발생하지 않았고, 임시 PNG 프레임은 남기지 않았다.

## 2026-08-08 — 몬스터 모션-SFX 브라우저 MVP

### 작업 목표와 승인 범위

GIF를 대량으로 만들지 않고 Unity Editor에서 모션과 SFX를 동시에 비교해 빠르게 후보를 고르는 도구를 추가했다.

### 생성 파일

- `Assets/Editor/Tools/Audio/MonsterMotionSfxBrowser.cs`
- `Assets/Editor/Tools/Audio/MonsterMotionSfxMappingAsset.cs`
- 각 스크립트의 Unity `.meta` 파일

### 기능

- `JC Tool/Animation/몬스터 모션 + SFX 브라우저` 메뉴로 창을 연다.
- 05_Art 몬스터 프리팹과 모든 유효한 AnimationClip을 목록으로 표시한다.
- 05_Art 프리팹이 원본 ThirdParty 프리팹을 참조하는 래퍼 구조일 때 연결된 원본 Animator까지 탐색한다.
- `PreviewRenderUtility`로 임시 인스턴스를 정면에 가깝게 렌더링한다.
- 기존 `SfxEditorAudioPreview`를 재사용해 AudioClip을 에디터에서 재생한다.
- 모션 시간, SFX 지연, SFX 볼륨, 정면 회전, 모션 반복을 조절할 수 있다.
- 선택한 조합은 `MonsterMotionSfxMappings.asset`에 별도 저장하며, 사용 전까지 해당 asset을 자동 생성하지 않는다.

### 책임 분리와 의존성

- `MonsterMotionSfxBrowser`: 목록 표시, 입력 처리, 임시 모션 렌더링, 재생 제어 담당
- `SfxEditorAudioPreview`: 기존 Unity 내부 AudioUtil 호출과 오디오 미리듣기 담당
- `MonsterMotionSfxMappingAsset`: 선택된 모션-SFX 조합의 저장 데이터 담당
- 원본 프리팹·씬·런타임 코드와 분리된 Editor 전용 도구로 구성해 게임 실행 구조에 영향을 주지 않게 했다.

### 검증

- 스크립트 중괄호 구조와 `git diff --check`를 통과했다.
- Unity 6.0.3.15f1의 기존 에디터가 프로젝트를 열고 있어 별도 배치 컴파일은 Unity의 중복 프로젝트 잠금으로 실행되지 않았다.
- 최초 파일 추가 시 Unity 에디터의 스크립트 재컴파일 로그에서 해당 변경과 관련한 컴파일 오류는 발견되지 않았다.

### 사용 방법

1. Unity에서 `JC Tool > Animation > 몬스터 모션 + SFX 브라우저`를 연다.
2. 오른쪽 SFX 폴더를 필요한 후보 폴더로 지정하고 `전체 새로고침`을 누른다.
3. 몬스터와 모션을 선택한 뒤 SFX 검색어를 입력한다.
4. `재생`, `SFX 지연`, `SFX 볼륨`으로 조합을 비교한다.
5. 채택할 때 `현재 조합 저장`을 누른다.

## 2026-08-08 — 모션 브라우저 URP·AnimationMode 오류 수정

### 확인된 문제

- 프로젝트가 URP를 사용하는데 미리보기 머티리얼을 Built-in `Standard` 셰이더로 강제해 마젠타가 표시될 수 있었다.
- `AnimationMode.SampleAnimationClip` 직후 `StopAnimationMode`를 호출해 샘플링된 포즈가 원래 포즈로 되돌아갈 수 있었다.
- `Failed to ad separator`는 도구 컴파일 오류가 아니라 Unity Editor 메뉴 계층에서 발생하는 별도 UI 로그였다.

### 수정 내용

- URP Lit/Unlit 셰이더를 우선 사용하고, 호환되지 않는 원본 머티리얼만 임시 머티리얼로 대체했다.
- 텍스처와 색상은 `_BaseMap`, `_MainTex`, `_BaseColor`, `_Color`를 순서에 맞게 복사한다.
- 미리보기 인스턴스가 존재하는 동안 AnimationMode를 유지하고, 창을 닫거나 대상을 교체할 때만 종료한다.
- 원본 씬·프리팹·머티리얼 에셋은 수정하지 않았다.

### 검증 상태

- 변경 파일의 `git diff --check` 통과
- 현재 실행 중인 Unity 프로세스가 최신 소스 변경 후 Editor Assembly를 갱신하지 않아, Unity 재시작 후 최종 동작 확인이 필요하다.

- 검색 결과 인덱스는 검색어가 바뀔 때만 다시 계산한다.
- 기본 SFX 폴더는 `Assets/ThirdParty/11_사운드`로 지정했다.

- SFX 후보를 검색하지 않는 동안 AudioClip 전체 로딩이 발생하지 않는다.
- 후보를 클릭하는 순간에만 해당 파일의 Unity 에셋 로딩 비용이 발생한다.

## 2026-08-08 — 일부 모션 미재생 수정

### 원인

- `AnimationMode.SampleAnimationClip`을 `BeginSampling`과 `EndSampling` 사이에서 호출하지 않아, 클립마다 애니메이션 바인딩이 달라질 때 일부 속성이 원래 값으로 돌아갈 수 있었다.

## 2026-08-09 — 모션 샘플링 및 Toon 머티리얼 재수정

### 최종 확인에서 드러난 문제

- 수동 `PlayableGraph.Evaluate`는 호출 자체는 성공해도 실제 Transform 포즈가 갱신됐다는 보장이 없어, Castle처럼 Animator/Avatar 구조가 복잡한 프리팹에서 고정 포즈가 남을 수 있었다.
- 상어 머티리얼의 셰이더 이름은 `Toon/Toon`인데 기존 호환성 검사가 URP와 Shader Graph 이름만 허용했다. 그 결과 Unity Toon Shader 머티리얼이 fallback 머티리얼로 교체되어 색과 표면 표현이 달라졌다.
- fallback이 필요한 투명 머티리얼은 텍스처와 색만 복사하고 알파 블렌드, ZWrite, RenderQueue를 복사하지 않아 얼굴·눈처럼 투명도가 필요한 부분이 잘못 표시될 수 있었다.

### 적용한 수정

1. `AnimationClipPlayable`, `AnimationPlayableOutput`, 수동 `PlayableGraph` 재생 경로를 제거했다.
2. 프로젝트의 GIF 추출기에서 이미 사용해 정상 동작을 확인한 `AnimationMode.StartAnimationMode → SampleAnimationClip` 방식으로 시간별 포즈를 샘플링한다.
3. 샘플링 중 원본 Controller가 포즈를 덮어쓰지 않도록 임시 프리뷰 인스턴스의 Animator만 비활성화한다. 원본 프리팹의 Controller·Avatar·AnimationClip은 수정하지 않는다.
4. `Toon/`으로 시작하는 지원 셰이더는 fallback 대상으로 오판하지 않고 원본 머티리얼을 그대로 사용한다.
5. fallback이 필요한 경우 투명 여부와 알파 클립 여부를 확인해 `_Surface`, `_Blend`, `_SrcBlend`, `_DstBlend`, `_ZWrite`, `_AlphaClip`, `_Cutoff`, RenderType, RenderQueue를 가능한 범위에서 보존한다.

### 책임 분리와 학습 포인트

- `EvaluateMotion`은 현재 시간의 애니메이션 포즈 샘플링만 담당한다.
- `PreparePreviewAnimators`는 임시 인스턴스의 Controller 간섭 방지만 담당한다.
- `ApplyPreviewMaterials`와 `CreateFallbackMaterial`은 PreviewRenderUtility에서만 사용할 머티리얼 변환을 담당한다.
- `ResolveAnimationPrefab`과 `MotionEntry`는 05_Art 래퍼와 ThirdParty 중첩 원본의 역할을 분리한다. 저장 기준은 05_Art 프리팹이고, 재생 기준은 실제 Animator가 들어 있는 중첩 원본 프리팹이다.

### 검증 결과

- `dotnet build Assembly-CSharp-Editor.csproj --no-restore --nologo --verbosity:minimal`: 오류 0개, 경고 0개.
- 소스에서 `PlayableGraph`, `AnimationClipPlayable`, `SamplePlayableGraph` 의존이 제거된 것을 확인했다.
- `Toon/` 셰이더 예외 처리와 투명 머티리얼 보존 코드가 포함된 것을 확인했다.
- Unity Editor는 실행 중이지만, 이번 수정 후 Castle/상어를 실제 선택해 재생한 새 Console 로그는 아직 생성되지 않았다. 따라서 Unity에서 스크립트 재컴파일이 끝난 뒤 Castle의 `Attack01` 또는 `WalkFWD`, 상어의 `Attack`을 선택해 시간 슬라이더를 움직이는 최종 수동 확인이 필요하다.
- 수정 범위는 `Assets/Editor/Tools/Audio/MonsterMotionSfxBrowser.cs`와 이 작업 기록 문서이며, 기존 씬·프리팹·FBX·Avatar·Controller·머티리얼 에셋은 수정하지 않았다.

## 2026-08-09 — 모션 브라우저 재생·상어 얼굴·정면 방향 수정

이전 진단에서 확인한 세 가지 문제를 브라우저의 임시 미리보기 범위에서 수정했다.

### 1. 모션 재생 처리

#### 변경 전 문제

- 모든 임시 Animator를 비활성화한 뒤 `AnimationMode.SampleAnimationClip`만 호출했다.
- 샘플링 호출이 예외 없이 끝나면 실제 Transform이 움직였는지 확인하지 않았다.
- 클립에 Transform 커브가 없거나 바인딩 경로가 프리팹과 달라도 정상 재생으로 표시될 수 있었다.

#### 변경 내용

- 임시 프리뷰 Animator를 다시 활성화하고 `speed = 0`으로 설정해 Controller가 자동으로 시간을 진행하지 않게 했다.
- `AnimationMode.BeginSampling → SampleAnimationClip → EndSampling`을 항상 짝으로 호출한다.
- 선택한 클립의 Transform 커브 개수, 프리팹과 일치하는 바인딩 개수, 실제 값 변화가 있는 커브 개수를 분석한다.
- 바인딩 누락이나 값 변화가 없으면 상태 표시줄에 경고해 “샘플링 호출 성공”과 “실제 포즈 변화”를 구분한다.

이 구조는 Animator의 책임과 클립 샘플링의 책임을 섞지 않으면서도, 잘못된 클립을 정상 모션으로 오판하는 문제를 줄인다.

### 2. 상어 얼굴 머티리얼

#### 확인된 원본 구조

- 상어 본체: Unity Toon Shader의 `Toon/Toon`
- `Dino_Shark01` 얼굴: `Dino_Face24`, Built-in Standard, `_ALPHAPREMULTIPLY_ON`, `_Mode: 3`, `_ZWrite: 0`
- `Dino_Shark13` 얼굴: `Dino_Face23`, Built-in Standard, `_ALPHAPREMULTIPLY_ON`, `_Mode: 3`, `_ZWrite: 0`
- 얼굴 PNG 텍스처는 투명 알파를 가진 정상 텍스처다.

#### 변경 내용

- `Toon/Toon` 본체 머티리얼은 원본을 그대로 사용한다.
- 투명 원본 머티리얼은 URP Unlit fallback을 우선 사용해 조명 때문에 얼굴이 검게 변하는 영향을 줄인다.
- `_Mode`, `_ALPHAPREMULTIPLY_ON`, `_ALPHATEST_ON`, `_SrcBlend`, `_DstBlend`, `_ZWrite`, `_Surface`, RenderType, RenderQueue를 기준으로 투명도 설정을 임시 머티리얼에 반영한다.
- 텍스처와 색상은 기존 머티리얼에서 복사하며, 생성한 fallback 머티리얼은 미리보기 종료 시 삭제한다.

### 3. 정면 방향

ThirdParty Dino Shark 미리보기 씬의 카메라가 모델의 +Z 쪽에 위치하고 -Z 방향을 바라보는 것을 확인했다. 기존 브라우저는 카메라를 -Z 쪽에 두고 +Z 방향을 바라보고 있어 모델의 뒷면을 볼 가능성이 있었다.

- 프리뷰 카메라 방향을 +Z 전방 기준으로 변경했다.
- 몬스터를 선택할 때 이전 몬스터의 수동 회전값이 남지 않도록 Preview 회전값을 0으로 초기화한다.
- 회전 보정은 계속 임시 Preview Root에만 적용한다.
